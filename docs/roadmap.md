# 路线图

本路线图是工程顺序和验收目标，不是发布日期承诺。当前版本为 `0.1.0-alpha.0`，只覆盖 M0 范围；其他阶段均未完成。

| 阶段 | 状态 | 交付范围 | 阶段验收依据 |
| --- | --- | --- | --- |
| M0：项目起点 | 当前版本 | 能力注册、单账号后端约束、内存发送状态、只读 HTTP Doctor | 类型检查、本地测试、构建；记录模拟服务验证与实机验证的区别 |
| M1：事件与连接 | 计划 | 规范化事件契约、首个后端适配器、WebSocket 连接管理 | 脱敏事件样例、连接断开与恢复测试、字段转换测试、不支持事件的可见处理 |
| M2：持久化基础 | 计划 | 账号与消息标识映射、事件记录、任务队列、迁移与恢复 | 进程中止后恢复、重复事件、数据库升级回退、数据一致性测试 |
| M3：受控发送与真机 | 计划 | 有范围限制的发送入口、未知结果核对、必要的媒体能力、真实环境验收 | 自有测试账号和获准会话的真实收发证据、故障场景、版本兼容矩阵 |
| M4：应用接口 | 计划 | SDK、MCP、稳定的能力发现与工具契约 | 工具发现与调用逐项对应、参数和错误语义一致、客户端集成验证 |

## M0：明确起点

当前 Doctor 只查询 `get_version_info`、`get_status` 和 `get_login_info`。Core 不提供持久化，也没有实现真实 QQ 登录或发送。当前不使用“完整网关”“全接口兼容”或“生产可用”描述本版本。

## M1：先把事件接准确

建立账号、会话、消息引用、事件时间与来源的统一模型。WebSocket 阶段处理连接生命周期和重连，输出可验证的连接状态。后端扩展保留命名空间，无法转换的语义明确标记，不悄悄编造通用字段。

本阶段的联网测试不自动获得向其他人发消息的权限。接收测试和主动发送测试分开安排。

## M2：让状态经得起重启

引入存储前先确定数据模型、升级策略与备份恢复方式。保存后端消息标识和统一引用之间的映射，让回复、撤回与资源查询有依据。任务队列区分已知失败和未知执行结果，恢复后不会因缺少内存状态而重新发送。

本阶段完成前，不承诺重启后仍可恢复任务，不承诺“恰好一次”投递。

## M3：用真实环境验证必要功能

从受限的文本收发开始，再逐项扩展回复、提及、媒体、文件和撤回。每项能力记录后端版本、平台、测试日期与已知限制。先保证一个明确环境中的真实行为，再扩展 Windows、Linux x64 或 ARM64；构建支持与真实运行支持分别列示。

发布兼容矩阵时，区分“仅声明”“模拟测试通过”“实机通过”和“已知不支持”。不以 API 注册数量或测试断言数量替代业务验收。

## M4：把能力交给应用

SDK 和 MCP 共享统一能力描述，明确区分读取操作和产生外部副作用的操作。MCP 工具名称使用显式注册表；每个工具应能从发现、参数验证一路追踪到实际执行结果。未实现或未通过验证的功能不因出现在文档中就默认开放。

## 暂无实施承诺的方向

自研 QQ 原生协议、登录组件、桌面客户端、自动安装第三方后端和多账号分布式调度，均不属于当前承诺范围。若后续立项，应单独给出实现来源、许可、维护成本和验收计划。
