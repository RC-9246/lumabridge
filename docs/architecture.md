# 架构说明

本文描述 `0.1.0-alpha.0` 已有边界和后续设计方向。标为“计划”的部分尚未实现。

## 当前结构

```text
开发者 / 本地命令行
        │
        ├── Core
        │     ├── 能力注册
        │     ├── 单账号后端约束
        │     └── 内存中的发送状态模型
        │
        └── Doctor ── OneBot HTTP ── 用户自行管理的后端
                       只读三个动作
```

Core 是可测试的独立模型。Doctor 是连接诊断入口。当前没有对外监听的网关服务，也没有把应用消息自动转交给 QQ 后端的生产链路。

## Core 的职责

能力注册用于显式描述后端能够提供的操作，而不是根据项目名称猜测“应该支持”。能力声明与真实运行结果仍需区别：一次成功的状态查询不能证明文件上传、消息撤回等其他能力可用。

当前能力状态为 `implemented`、`unsupported`、`experimental`、`unverified`。只有注册为 `implemented` 且活动驱动也声明支持的动作才能进入执行；这个状态表示实现声明，不等于实机验收结论。

单账号后端约束用于避免同一账号同时交由多个活动后端执行动作。当前模型不提供分布式锁，不能阻止另一个进程、另一台主机或用户直接启动的后端使用同一账号。

每次激活或停用后端都会更新账号的会话代数。执行前发现会话已变更时拒绝操作；执行期间发生变更时，结果标为未知，不把同一次操作转交给新后端。已经交给驱动的外部操作无法靠切换本地状态撤销。

发送状态模型用于表达一次操作在本地的进展和结果。当前没有真实发送入口、持久化存储、崩溃恢复或跨进程协调。进程退出后，内存状态不保留；模型测试通过不能证明消息实际到达 QQ。

| 状态 | 当前语义 |
| --- | --- |
| `accepted` | 驱动接受或排队处理了操作；可附带回执 |
| `confirmed` | 驱动返回了非空回执；不表示接收者已收到或阅读 |
| `failed` | 本地检查拒绝，或驱动明确返回失败 |
| `unknown` | 驱动异常、响应无效，或执行期间会话改变，结果无法确认 |

协调器对一次操作最多调用一次驱动，不自动重试未知结果。`BackendDriver` 是实现接口；本版本没有随附能够发送 QQ 消息的驱动。

协调器当前不提供执行超时，驱动实现必须自行保证请求有界结束。操作结果返回给调用者，不在协调器中保留历史；持久化结果和崩溃恢复属于后续里程碑。

## Doctor 的职责

Doctor 从本地 JSON 配置读取后端 URL、token 环境变量名和整次诊断的超时时间。token 由指定环境变量提供，不应写入配置或仓库。

诊断范围固定为：

| 动作 | 诊断用途 | 不能据此推导 |
| --- | --- | --- |
| `get_version_info` | 读取后端自报实现和版本信息 | 该版本的所有接口都符合预期 |
| `get_status` | 读取后端自报运行状态 | 网络、登录及所有业务动作始终正常 |
| `get_login_info` | 检查登录信息查询是否可用 | 已完成真实消息发送、接收或送达验证 |

Doctor 不负责安装或更新第三方后端，不执行登录、发送、删除、重启或配置修改。连接失败、超时或异常响应必须保留为诊断结果，不能包装成成功。

## 计划中的数据流

```text
应用 / SDK / MCP（计划）
          │
          ▼
统一动作与事件契约（计划）
          │
          ├── 能力检查与参数校验
          ├── 账号和会话范围
          ├── 持久化映射与任务状态（计划）
          └── 后端适配器（计划）
                    │
                    ▼
           用户自行管理的后端
```

协议入口和后端适配器应围绕统一模型连接，避免将一个外部协议的全部字段当成内部领域模型。首个可运行版本只交付必要范围，未实现的能力应明确报告不支持。

## 后续实现应保持的约束

### 消息身份

不同后端的 `message_id`、消息序号和原生标识不能假定互换。计划中的消息引用应保留账号、会话、后端和原始标识之间的关系；历史标识映射丢失时，应明确报错，不猜测撤回或回复目标。

### 发送结果

本地创建任务、后端接受请求和消息实际送达是不同证据。发生超时后，后端可能已经执行发送；未来队列应保留“结果未知”的状态，并提供核对流程，避免自动重复发送。当前版本没有实现这个持久化流程。

### 资源生命周期

图片、语音、视频和文件可能对应本机路径、短期 URL 或后端缓存。未来资源接口需要描述来源、有效期和可访问范围，不应把后端本地路径直接当成应用可下载的公共 URL。

### 事件处理

事件适配器应保留原始来源和必要的后端扩展。去重、重连补偿、顺序与缺口处理将在 WebSocket 和持久化阶段分别验证；当前没有事件消费能力或持久化事件日志。

### 后端替换

替换后端不等于迁移 QQ 登录态。未来切换流程需要停止旧执行入口、检查新后端能力、确认消息标识边界并提供回退方法。当前没有自动迁移或无缝切换功能。

## 验证边界

类型检查与本地测试验证代码契约；模拟 HTTP 服务验证请求和响应处理；真实账号环境验证后端行为。三者分别记录，不能互相替代。后续 ARM64 验收必须记录操作系统、运行时、后端版本及真实测试范围，不能由 x64 构建成功推断。
